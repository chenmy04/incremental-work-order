# 执行者纪律（复制进主树：`docs/implementation/executor-charter.md`，所有执行者共用一份）

> 流程规则见主树 `docs/implementation/README.md`（唯一规则文本）。本文件只写**纪律**，不复制规则正文。

## 角色

你消费的是**你自己那棵树**的队列切片（`docs/implementation/work-orders/**` 里属于它的单）。
**你不替用户做架构裁决，也不替调度者做产品决策**：遇到该由人拍的事，标成阻塞写进本树 status 并继续做别的。

## 每个阶段边界（= 每次阶段性提交之前）

重读：本树 `worktree-charter.md` 与 `work-orders/**`；主树 `README.md`（§3 规则 / §4 纪律）、
`manifest.json`（队列与依赖条件）、`status.md`、`rulings.md`。新单与修订由调度者**直投进你的
`work-orders/`**——不需要去别处复制，也没有副本要合并。

## 节奏

- **连续跑**：单内不停（普通 bug、测试失败、阶段切换都不是停止理由）。
- **批末**：打 `git tag -a checkpoint/<批次名> -m "<范围> done; suite <计数>; <日期>"`，把检查点报告写进本树
  `status.md`，**然后立刻继续下一批**，不等确认。检查点是给调度者与用户的**可选检视窗口**，不是闸门。
- **升级 ≠ 停下**：需要人拍的部分标阻塞写进本树 status，继续做不受影响的其它单；整队卡死才停。
- **修订回执**：纳入修订后，下个阶段提交信息或本树 status 里记 `已纳入 work order <N> 修订 @<sha>`。

## 纪律（违反即返工）

- **写权**：只写工单声明的 `write_paths`；`forbidden_write_roots` 一律不碰；**主树的文件、别的子树、
  发布源一律不写**（只读）。
- **不改历史、不越界**：不 `reset`/`stash`/`clean`、不 `merge` 主干、**不 push**；只显式
  `git add -- <paths>`（禁止 `add .` / `-A`）。合并回主树是用户批准后的独立动作，不是你的动作。
- **不改契约**：契约（`work-orders/**`）有问题 → 交回调度者改并投递新版本；你只在自己那份里追加阶段进度与注释。
- **事实分级**：实测（带 `文件:行`/实测值）/ 引用（标来源与时间）/ 未验证（写"待核实"+验证方法）。
  **不得把未验证写成实测**；没有观测证据的能力一律声明 false。
- **门要能被证伪**：每道门配反例，并写明"资源缺席/未知时的行为"（缺席必须失败）。跑不了的门如实写"未跑"，
  **不得放宽断言凑绿**；缺项写 PARTIAL 并逐条列剩余项。
- **凭据与受保护数据**：凭据只作 locator，绝不复制进仓库/日志/证据；受保护路径不读、不改、不 stage。
- **不做别人的活**：别的执行者的切片、以及"顺手"的重构/格式化，都不做（那是新工单的事）。

## 收尾

- 每阶段提交一次；本树 `status.md` 由你维护（每单终态、已知缺口、阻塞项）。
- 每张单按它自己的格式给全：门逐条 / 回归计数与退出码 / 摘要 / 费用与请求数 / 清理证据 / 未做项 /
  **唯一终态码**（`<...>_DONE` 或 `<...>_PARTIAL`）。
- 不得用一份报告冒充多份，不得用局部通过冒充整门通过，不得用假端点结果冒充真实结果。
